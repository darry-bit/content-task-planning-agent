## 设计取舍

选择单 Agent 和 CLI，使评审能用命令直接复现核心行为。业务工具使用本地合成数据，故障、费用、耗时规则可控；真实模型负责动作选择，程序负责执行和强约束。

模型每次读取用户约束、最新计划、成功成果、账本、工具观察和剩余调用额度，返回动作、参数、公开简短依据。返回格式不合法或未知工具也转为可观察错误，受调用上限控制。不要记录内部思维过程。

计划修改需要关联版本；估算绑定方案版本；保存仅接受当前有效估算。程序生成最终状态，模型不能自行宣称工具保存成功。预计总费用不等于历史估算之和。

工具不根据模型提供的任意路径写文件；保存位置由 CLI 管理。合成素材视为数据，不能变成系统指令。Trace 不记录密钥、认证头或环境变量内容。

## 分阶段任务

1. 输入与约束：实现输入校验、固定时钟、预算/时间计算。
   - 验收：缺字段、非法值、边界金额、时区、时间不足测试通过。
   - 文件：输入/规则模块、规则数据、约束测试。
2. 正常纵向链路：四个工具、执行状态和离线 CLI。
   - 验收：一个正常案例生成可读取的方案、输出和 Trace。
   - 文件：工具、执行器、CLI、端到端测试、正常案例。
3. 反馈与重规划：错误观察、超预算反馈、方案版本失效与结果复用。
   - 验收：失败后不误报成功；成功结果保留；新方案必须重新估算。
   - 文件：执行器、Mock 策略、异常测试、异常输入案例。
4. 真实模型适配：根据供应商官方文档实现协议和环境变量配置。
   - 验收：使用本地受控响应验证协议解析、错误和超时；真实验收另行标记。
   - 文件：模型适配器、提示、协议测试、环境示例、README。
5. 验收与交付：保存离线实际案例，撰写评估、AI 使用与复盘。
   - 验收：命令可复现；文档与实测一致；至少三组材料覆盖必选点。
   - 文件：examples、评估文档、AI 使用记录、复盘、README。
6. 可选加分：重复执行与失败后续跑。
   - 验收：同一执行不会重复保存或重复记费；不同输入不能复用旧状态。

每一阶段先写行为测试并确认失败，再实现、运行、检查输出。相关测试通过后再进入下一阶段。Git 提交应使用真实提交者身份，不能伪造用户手写历史。

## 风险与处理

- 模型不可用：保留 Mock 入口，明确只证明流程；不可伪造 live 结果。
- 模型选择不稳定：错误可观察、限制调用、硬校验最终方案；不要求每次路径完全一致。
- 截止日期过期：测试使用注入时钟；live 示例运行前更新截止时间。
- 费用精度与复用：使用明确数值规则，测试多次估算和重复执行。
- 范围膨胀：优先必选验收，续跑与幂等在核心链路完成后决定。

循环允许使用固定工具依赖骨架，实际下一动作由 model.decide 返回。live 与 mock 使用同一执行器；执行器没有“超预算自动换 economy”的分支。此分支仅在离线 Mock 中存在并明确披露。

`generate_script` 是本地登记与校验工具，真正的 live 脚本内容由模型在参数中生成；没有隐藏的第二次模型调用。模型输入每轮是状态快照，其中包含已有计划、规则、步骤、历史工具观察和实际时钟。快照方式使检查点容易复现，代价是多轮输入可能较长。

根据 [OpenAI 官方函数调用文档](https://developers.openai.com/api/docs/guides/function-calling)，适配器提供函数 schema 并解析 function_call。使用严格字段约束、单次工具调用，记录公开依据及 usage，不记录内部推理输出。返回的动作仍由本地工具校验。

## 已验证的关键取舍

- 故障后重新估算保留同一脚本版本，未重复收取生成费用。
- 预算调整采用新方案版本；旧估算失效，历史费用仍保留。
- 状态文件是权威检查点；Trace 和输出可从状态生成。
- 没有加入业务框架或第三方运行依赖；构建后端使用 setuptools。
- 本地 Git 初版作者为 `Codex AI`，不将 AI 生成记录伪装成用户手写提交。
