# 复盘、实际投入与下一步

## 实际投入与范围

从首份规格文件创建（2026-10-28 10:56，中国标准时间）到真实验收汇总（12:29）的可观察历时约 93 分钟；这是含沟通、工具等待和环境处理的 AI 辅助开发阶段历时，不是用户净编码工时，也不包含之后的最终文档整理与 GitHub 交付。用户人工用时未单独计时。界面、线上部署、多 Agent 和生产 Runtime 未实施，题目也未将它们列为必需。

## 实际难点和处理

1. 重规划时需要区分已发生工具费与当前制作费。历史估算不累加，但旧工具调用不能退款；预算真实案例因此是 12.70 → 7.10，而不是简单把制作费 12 改成 6。
2. 估算失败不能清空成功脚本，改素材却必须让旧估算失效。使用方案版本和独立状态保存兼顾复用与有效性。
3. 模型不能用一句“完成”绕过保存。最终 completed 只由本地工具成功保存且通过硬校验后设置。
4. 模型 schema 不是可信边界。审查发现渠道为列表/对象会崩溃，先写失败测试，再把类型错误变成可观察的 INVALID_ARGUMENTS。
5. 云端供应商协议并非完全相同。DeepSeek 与百炼使用不同的非思考参数，Qwen 不依赖 required；本地校验始终保留。供应商、协议及模型身份进入检查点，防止误续跑。
6. Mock 跑通仍不足以证明 Agent。最终用真实模型观察到工具故障恢复与预算重规划，并保留正常路径直接选择低成本方案的事实。

## 从实测得到的认识

真实模型可以直接选择合适的便宜方案，不一定先犯错。预算重规划验收通过合成的高品质初稿偏好触发，而不是修改日志或在程序里强制降级。故障注入与调用上限让失败可重复观察；完整 Trace 和账本比截图更有验证价值。

真实文案仍可能带入未提供的设施或参与规则；当前输出应作为运营草稿，不能未经核实直接发布。此问题作为局限公开保留，没有润色或删除不完美的原始 Trace。
