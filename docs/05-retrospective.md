# 初版复盘

以下是 AI 实施过程中实际遇到的问题与取舍，不代表用户已经亲历或掌握。用户应在亲自运行、修改和验证后补充自己的部分。

## 实际难点与处理

1. **费用不能在重规划时重复累计。** 估算属于当前方案快照，历史调用费用属于不可撤销账本。调整后制作费从 12 变为 8，但旧工具费继续存在；因此离线预算案例最终为 9.10。测试覆盖了保存费用预留和小数边界。
2. **部分成功与新方案失效要同时处理。** 临时估算故障不应清空脚本；换素材或渠道却必须使旧估算失效。用方案版本绑定当前估算，历史步骤保持真实状态。
3. **模型的成功声明不能作为最终状态。** 本地保存和约束校验成功后，程序才将任务置为 completed；模型选择 finish 时只表示未完成停止。
4. **模型 schema 不能替代程序边界检查。** 审查发现渠道字段为列表或对象时会抛 TypeError，先写回归测试再补显式类型检查。该修复由 AI 完成。
5. **环境问题与逻辑问题需要分开诊断。** 系统 Python 命令指向不可执行的 Windows 别名，改用可用的 Python 3.12.14 运行时；沙箱系统临时目录无权限，改用工作区临时目录。未通过跳过测试掩盖问题。

## 当前取舍

选择标准库和 CLI，减少依赖及界面工作，优先证明执行路径、约束和失败处理。业务工具本地化便于故障注入和确定性验证。选择状态快照作为模型上下文，简化恢复，但可能增加 token 消耗。

Mock 用固定策略保证测试可复现，live 模式由模型自行选动作；两者共享执行器。离线通过不等于真实模型通过，最终仍需真实运行证据。

## 下一步优先级

1. 选择真实模型，运行正常与故障路径，记录内容质量和决策效果；失败时先保留记录再修改。
2. 用户亲自完成一个有业务意义的改进，给出修改前后的测试和 Trace。
3. 确认真实验收和个人实践记录后，推送 GitHub，填写题号、URL、最终 SHA。
4. 若继续工程化，再考虑素材授权、真实检索、并发控制和事务恢复；首版不把这些未实现项包装成能力。
