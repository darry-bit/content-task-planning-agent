# 初版代码审查记录

供应商扩展审查：核对两家官方协议，隔离密钥、模型和根地址；保持 HTTP 脱敏与禁止重定向；Chat 不保存 reasoning_content，不执行多调用的任意子集。Qwen 使用 auto，纯文本响应会明确 MODEL_ERROR，不保证每次都选择工具。供应商阶段 46 项测试通过；最终包含证据检查共 51 项，并完成真实 DeepSeek 调用。

审查人：Codex AI，属于同一 AI 的自查，不是独立人工或另一模型审查。没有执行生产安全审计。

## 正确性

对照规格核对四个工具依赖、方案版本、费用账本和保存状态；检查测试及 8 组 CLI 的 Trace。保存结果与当前计划和费用一致，缺信息案例未开始工具执行，无可行案例无保存文件。失败历史保持 failed。

发现并修复：渠道字段为列表/对象时会因字典成员查询抛 TypeError。先写失败测试，再补类型校验；改为 INVALID_ARGUMENTS 观察。

## 可读性与架构

模型适配器只返回动作；工具执行和硬校验集中于 Engine；CLI 管理路径和检查点。Mock 策略与 live 模式分开，明确固定分支只用于离线验证。业务规则使用一个随包发布的合成 JSON 文件。

## 安全边界

模型不能指定任意保存路径；工具参数必须匹配预期字段。API 密钥仅来自环境变量，不写入检查点或 Trace；HTTP 错误不输出服务正文；适配器拒绝不安全 URL 和认证信息，并禁止自动重定向。模型输出仍需本地校验。未对任意手工篡改检查点提供完整防护。

## 性能与资源

累计动作上限最大 50，连续三次动作失败停止；单次网络超时 45 秒，不隐式重试；响应大小有限制。每轮完整快照增加输入 token 消耗，但首版规模可控，未做性能优化或并发扩展。

## 验证与结论

初版 37 项、供应商阶段 46 项、最终 51 项测试通过；8 组离线与 4 组真实基础案例通过，真实失败续跑与完成结果重复读取通过，构建安装和安装后的模块入口通过。最终证据检查还核对账本、Trace、产物一致性及哈希。路径见 `03-evaluation.md`。
