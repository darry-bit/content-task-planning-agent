# 内容任务规划 Agent：实现规格 v0.1

范围已由用户于 2026-10-28 回复“按这个做”确认。当前实现与离线验收见 `03-evaluation.md`；真实模型效果仍待验证。

## 1. 目标与假设

面向运营人员，在给定预算和截止时间内生成并保存一份可执行的内容活动方案；无法完成时明确说明原因、缺口和已保留成果。

已确认选择：Python 3.11+、CLI、单 Agent；业务工具和素材使用本地合成数据。模型适配器提供真实模型模式与离线 Mock 模式。首版不做界面、部署、多 Agent。

作业截图为验收依据，不把截图中的示例仓库视为完整答案。所有生成代码和文档均应如实披露 AI 辅助；用户尚未作出的修改不得列为个人贡献。

## 2. 输入与输出

输入 JSON：主题、预算、带时区的截止时间；测试可注入固定当前时间。预算单位为模拟单位，并非真实人民币或模型账单。

```json
{
  "theme": "校园咖啡店期末促销",
  "budget": 10,
  "deadline": "2026-11-01T18:00:00+08:00"
}
```

缺少主题、预算或截止时间时返回 needs_input 和缺失字段，不调用收费业务工具，不替用户猜测。拒绝负数、非有限预算、无时区或无法解析的日期。预算为零是合法输入，但不保证存在可行方案。

最终结果包含：输入约束、任务计划与依赖、步骤状态、工具结果摘要、费用明细与合计、预估剩余耗时、保存位置，或明确的未完成原因。只有文件保存成功才能报告 completed。

## 3. Agent 行为与边界

循环：模型选择一个动作及参数 → 程序校验并执行工具 → 将真实结果加入上下文 → 模型选择下一动作或结束。

四类工具：素材检索、脚本生成、成本估算、方案保存。模型需要基于成本超限、工具错误和部分成功结果选择调整、重试、替代或停止。程序只实施输入校验、依赖与预算约束、权限边界及步数上限，不能用固定 if/else 充当真实模型的重规划。

工具返回结构至少包含 ok、data 或 error、费用和耗时。重试由模型决策；限制重复失败次数及总工具调用次数。达到上限返回 incomplete 和停止原因。

成功步骤的输出保留。参数变化导致下游旧脚本或估算失效时，应标记旧结果被替代，不能用旧估算保存新方案。历史失败保留失败记录，不改写成成功。

费用采用明确账本：已发生的工具调用费用 + 当前方案预计制作费用 = 当前预计总费用。历史估算值不累加；失败调用是否收费由工具规则明确给出。真实模型 API 账单不纳入模拟单位，单独披露。

时间采用可检验的业务模拟：执行开始时间加已发生工具耗时，再加当前方案剩余制作耗时，不得超过截止时间。真实运行还须检查当前时间是否已经越过截止时间。保存前由程序再次校验预算、时间和依赖。

## 4. 技术、目录与代码风格

优先使用 Python 标准库降低复现成本。真实模型供应商及 HTTP 协议在接入前根据官方文档核实；密钥仅从环境变量读取。Mock 模式必须在输出和 Trace 中显式标注。

```text
README.md                  安装、运行、评审入口
src/content_agent/         CLI、决策循环、工具、模型适配器、状态
tests/                     可执行测试
examples/inputs/           验收输入
examples/runs/             实际输出、Trace、保存方案
data/                      合成素材、费用和耗时规则
docs/01-requirements.md     本规格
docs/02-solution.md         架构、取舍、实施任务
docs/03-evaluation.md       预期、实测、失败和限制
docs/04-ai-usage.md         AI 辅助与个人贡献证据
docs/05-retrospective.md    真实复盘与下一步
pyproject.toml             包信息与依赖
.env.example               环境变量名，不含密钥
```

命名使用 snake_case、函数有类型注解；工具错误使用稳定错误码，记录公开的简短决策依据，不记录模型内部思维链。例如：

```python
def estimate_cost(plan: dict, spent: float) -> dict:
    production_cost = sum(item["cost"] for item in plan["items"])
    return {"spent": spent, "production_cost": production_cost,
            "projected_total": spent + production_cost}
```

此片段仅说明风格；正式费用计算应处理数值精度和非法数据。

## 5. 运行命令

从项目根目录执行：

```powershell
python -m pip install -e .
$env:PYTHONPATH = "src"
python -m unittest discover -s tests -v
python -m content_agent --input examples/inputs/normal.json --mode mock --now 2026-10-28T10:00:00+08:00 --output local-runs/normal
python scripts/evaluate.py --output local-runs/evaluation
```

业务无法完成与程序崩溃应可区分。输出目录隔离不同案例，禁止无提示覆盖已有成果。退出码见 README。源码零安装入口为 `python run.py`；live 命令需先配置模型并更新实际截止时间，不能使用 `--now`。

## 6. 验收与测试策略

使用 unittest 做小规模单元测试和 CLI 集成测试；工具使用真实本地实现，外部模型边界使用受控替身。测试固定时钟和故障注入，避免依赖今天的日期。

| 验收点 | 可观察成功条件 |
| --- | --- |
| 正常完成 | 预算与时间满足，依赖完整，文件存在，状态 completed |
| 缺预算 | needs_input 列出 budget，不开始业务执行 |
| 缺截止时间 | needs_input 列出 deadline，不开始业务执行 |
| 工具失败 | 失败记录可见；后续决策基于错误，复用已成功成果 |
| 超预算后可调整 | 观察超限结果，模型修改方案，再估算后保存 |
| 无可行方案 | incomplete；缺口可计算；无虚假成功 |
| 时间不足 | 拒绝不可按时完成的保存，说明时间缺口 |
| 模型异常/调用上限 | 明确停止原因，不吞掉错误或无限循环 |

至少保存三组实际输入、输出和完整运行记录，共同覆盖所有必须验收点；建议保留上述独立案例。真实模型至少记录两条不同执行路径，包含一条根据工具反馈调整的路径。若只有 Mock 结果，必须标记“尚未验证真实模型动态决策”。

加分项：重复执行幂等、失败后续跑；需对输入与状态匹配做校验，并证明不会重复收费或误用旧结果。
