# AI 使用范围与个人贡献

## 使用原则

本项目允许 AI 辅助。代码、测试、文档起草及命令执行主要由 Codex AI 完成，不宣称用户独立手写核心算法或独立执行全部测试。所有 AI 生成提交明确标记作者 `Codex AI <codex@local.invalid>`，保留实际历史。

## 用户实际贡献与对应证据

| 用户实际工作 | 对项目的影响 | 可审查对应 |
| --- | --- | --- |
| 提供考试规则、交付规范与题目截图，选择题目 2 | 确定运营内容规划、预算、截止时间、动态决策及验证范围 | `01-requirements.md`、验收矩阵 |
| 确认 Python CLI、单 Agent 和本地合成工具的首版范围 | 将开发投入集中在可运行链路与证据，避免界面/部署占用时间 | `02-solution.md`、依赖与目录结构 |
| 提供已有 DeepSeek 与百炼渠道，明确直接调用云端 API | 增加供应商适配、凭据隔离与真实 DeepSeek 验收 | `chat_model.py`、`08-provider-setup.md`、live Trace |
| 指出离线初版不足以提交，要求逐条满足题目 | 推动真实模型的正常、故障、预算重规划及不可行案例落地，并增加提交证据检查 | `examples/manifest.json`、`verify_submission.py` |
| 配置本机 API Key、完成 GitHub 登录并明确仓库公开要求 | 使真实调用与公开仓库交付可执行；密钥未进入 Git | 真实 response ID、仓库可见性与最终提交 |

这些贡献集中于需求界定、工具渠道、验收目标和交付决策。核心代码与自动化验证主要由 AI 完成，个人工程实现贡献相对有限；不把 AI 的修复或测试冒充用户手写经历。

## AI 实际完成内容

- 解读题目、提出方案与规格，在用户确认后实现 CLI、执行循环、工具、约束、账本、检查点。
- 参照官方文档实现 Responses 与两家 Chat Completions 协议，编写测试与故障注入。
- 先写测试并观察失败，再实现相应功能；修复渠道非法类型问题。
- 使用用户授权的本机密钥调用真实 DeepSeek，归档实际输出与 Trace；执行失败续跑和幂等验证。
- 编写证据清单、检查脚本、运行说明、五份必交文档与逐条验收表；扫描密钥并交付 GitHub。

## 验证归属与限制

51 项测试、12 组基础验收、真实续跑及重复执行由 AI 实际执行，用户未被描述为亲自执行这些命令。真实效果有 Trace 和 response ID 支持；Mock 结果明确标记。未伪造内部推理、独立开发经历、人工修复记录或学习感想。

`06-personal-contribution-guide.md` 是可选后续实践路线，不是已经完成的个人经历。若用户之后自己修改，应按真实差异、测试及 commit 追加记录。
